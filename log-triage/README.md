# 日志体检器（log-triage）

> 把一堆日志变成一份"到底有几种错、什么时候开始、最早出现在哪"的报告。
> **排障最花时间的不是看日志，是从几千行里弄清楚到底有几种错。**

---

## 它回答四个问题

| 问题 | 看哪一节 |
|---|---|
| 一共多少行、覆盖多长时间？ | 报告头部 |
| 有几个级别、各多少条？ | 一、级别分布 |
| **错误归并成几类？每类何时首次出现、在哪个文件第几行？** | 二、错误类型 Top N |
| 什么时候开始密集出现？ | 四、可疑突增点 |

---

## 快速开始

```bash
python log_triage.py --log-dir <日志目录>
python log_triage.py --log-dir <目录> --all-files      # 递归子目录
python log_triage.py --log-dir <单个文件>               # 也支持单文件
python log_triage.py --log-dir <目录> --top 20
```

输出：`triage-report.md`（人看）+ `triage-summary.json`（机器读）。

**支持两种输入，自动识别**：

- **行式文本日志**（`.log` / `.txt` / `.out` / `.err`）——**流式逐行读**，
  100MB 的文件也不会撑爆内存
- **网关的 JSON 调用日志**（一次调用一个文件）——自动取出状态码与错误字段

**依赖：无。**只用 Python 标准库。测试也是标准库 `unittest`。

```bash
python -m unittest discover -s tests    # 33 项，全部毫秒级
```

## 核心：同类错误必须归并

不归并的话，Top N 里全是重复行，报告等于没做：

```
[123] Request aborted      ┐
Request aborted            ├─→  Request aborted          （1 类，11 次）
[  9] Request aborted      ┘
```

归并规则与执行顺序：

| 步骤 | 规则 | 例子变成 |
|---|---|---|
| ① **先剥前缀** | `[123]` / `(42)` / `#7`（线程号、错误码、行号） | `[123] Request aborted` → `Request aborted` |
| ② **再掩码 ID** | 完整 UUID / 长十六进制 / IP / Windows 路径 | `<uuid>` `<id>` `<ip>` `<path>` |
| ③ **最后折叠数字** | 剩余数字 | `after 123ms` → `after Nms` |

> 🔁 **跨工具统一（2026-10-11）**：这套规则与 `projects/model-call-report` 的
> `normalize_error()` 是**同一套**——同一条错误在两个工具里必须归成同一类；
> 空消息兜底同为「（无错误信息）」，截断同为 80 字符。**改这里必改那边。**

### 🔴 为什么顺序不能改（这个坑踩了两次）

把 ③ 提到 ② 前面，`[123] Request aborted` 会先变成 `[N] Request aborted`，
**前缀规则永远匹配不上，同类就被拆成两类**；
同理，先折叠数字会让 `8b1a01b6` 变成 `NbNaNbN`，十六进制正则也失效。

两次都是**被单元测试当场打回**的，不是看代码看出来的。

## 实测效果（真实日志，50 条调用记录）

| | 归并前 | 归并后 |
|---|---|---|
| 错误类型 | 18 条失败记录 | **4 类** |

加上"剥掉行首编号"这条规则之后，`Request aborted` 从两类（6 次 + 5 次）
合并成 **1 类 11 次**——这才是排障时真正想看到的粒度。

报告里还能直接读出：时间跨度 2026-10-06 → 10-10、最长的一次卡顿出现在哪一类。

## 隐私与安全

- **不输出完整日志行**，只输出级别、时间、归并后的错误类型。
  ⚠️ 但「错误类型」是去掉 ID/数字/路径后的**消息文本**，正文措辞仍可能保留
  —— 报告要给外人看之前，先人工过目一遍
- 认不出的级别归为「**未知**」，**不瞎猜成 INFO**（测试专门守这条）；
  JSON 日志缺 status 字段同样归「未知」，不猜成 ERROR（2026-10-11 复核补，测试守）

---

## 已知边界

- 只做**通用统计**，不理解具体业务语义（它不知道你的业务，只知道"哪类错最多"）
- **不做实时监控、不做告警推送**——这是**事后体检**工具
- 时间戳只识别 3 种常见格式，识别不到就留空（**不猜**）
- 突增检测看的是**小时错误行数 ≥ 错误中位数×3**（不足 3 条不算；中位数取常规定义，
  偶数样本取两值平均）—— 只看错误行，INFO 刷屏不会误判成突增（2026-10-11 复核修正）。
  粗口径，只作提示，不作结论
