# SPEC · Windows 机器巡检工具（windows-inspector）

> 状态：**待实现**（规格已定，可直接开工）
> 优先级：🥈（IT 支持 / 桌面运维 / 数字化专员岗对口，这块应届生几乎没人做过）
> 预估：1~2 天（PowerShell 你已熟）
> 归属：`projects/windows-inspector/`

---

## 1. 一句话

给一台 Windows 机器做体检，出一份人能看懂的报告：磁盘、端口、服务、计划任务、开机自启、最近的系统报错。

## 2. 形态

**交互式菜单脚本**（PowerShell），交付给**不懂技术的人也能用**——
这是关键：运维岗真正的日常是"给别人一台机器看看有什么问题"，不是自己写脚本。

```
1. 立即体检        2. 只看某个项目（如磁盘）      3. 导出报告到文件
4. 查看上次报告    q. 退出
```

## 3. 检查项（每一项都要给出**正常/警告/异常**三档判断，不只是打印数值）

| 项 | 看什么 | 异常示例 |
|---|---|---|
| 磁盘 | 各盘剩余空间 | 剩余 < 10% 或 < 10GB |
| 端口 | 常用端口是否被占用（80/443/3306/6379/20128…） | 关键端口被非预期进程占用 |
| 服务 | 关键服务状态（打印、网卡、Windows 更新等） | 服务 stopped 但设为自动 |
| 计划任务 | 列出第三方计划任务 + 上次运行结果 | 上次结果非 0（失败）却没人发现 |
| 开机自启 | 列出自启项，标出可疑项 | 指向不存在路径的程序 |
| 系统错误 | 最近 24h 的严重事件 | 磁盘错误、蓝屏、服务崩溃 |

## 4. 输出

- 终端：分级显示（正常/警告/异常用不同标记）
- 文件：导出 `机器名-体检报告-<时间戳>.md`
- 🔴 **脱敏是硬要求**：报告里**不得出现**用户名、机器名、IP、磁盘卷标。
  导出前一律替换为 `<已脱敏>`。**要有单元测试/断言专门守这条。**

## 5. 验收标准

- [ ] 在**本机真实跑通**，导出一份真实报告（脱敏后才能公开）
- [ ] 每一项都有明确的三档判断，不是只 print 原始数据
- [ ] 菜单式交互，非技术同事能独立操作
- [ ] 零第三方依赖（只用系统自带 cmdlet）
- [ ] README：怎么用 / 每项判据是什么 / **已知边界**

## 6. 明确不做

- 不做任何**修改**动作（不启停服务、不删自启、不清日志）——**只读体检**，
  改是另一件事，需要单独确认。这是安全和信任的红线。
- 不需要管理员权限才能跑（读普通信息）；需要权限的项要**明确提示**而不是静默失败

## 7. 面试可讲的点

> 「桌面运维的日常就是给一台 Windows 机器做体检、出一份别人看得懂的报告。
> 我写的巡检脚本覆盖磁盘、端口、服务、计划任务、开机自启和最近的系统报错，
> **每一项都给正常/警告/异常三档判断**，而不是只把数值打印出来。
> 它是**只读**的——体检和动手改是两件事。」

最后那两句（只读 / 三档判断 / 交付给不懂技术的人）是这个作品真正的加分点，**别在简历上丢掉**。
