# 说明 - 报告脱敏

> 项目：windows-inspector · 读者：完全不懂技术的第一次求职者 · 写作日期：2026-10-11

## ① 一句话是什么

把报告里的机器名、用户名这些隐私信息换掉再拿出门。

## ② 为什么需要它

体检报告要发给别人看（比如放进求职作品集），但报告里的机器名、用户名、内网地址能拼出「你是谁、你的电脑叫什么、你叫什么」。脱敏（Data Masking，把敏感信息替换成无意义替身文字的过程）让报告照样能说明问题，但认不出主人。

替换出来的假名字叫占位符（Placeholder，比如 `MACHINE-NAME`，表示「这里原来有个名字」的替身）。

没有它会怎样：报告发出去的同时，个人信息也发出去了，收不回来。

## ③ 在我们项目里长什么样

- 代码在 [Inspect-Windows.ps1](windows-inspector/Inspect-Windows.ps1) 的 `Protect-Text` 函数，统一替换四类信息：机器名、用户名、内网网际协议地址（IP，Internet Protocol，网络里标识一台机器的数字地址）、`C:\Users\用户名` 形式的用户目录路径
- 导出文件名也不含机器名——这点与 SPEC 字面建议有出入，已在 [README.md](windows-inspector/README.md) 的已知边界章节如实说明，没有静默处理
- **脱敏是断言不是口号**：[Test-Inspect.ps1](windows-inspector/Test-Inspect.ps1) 对导出报告做程序化验证，确认不含真实机器名和用户名，验证结果无泄漏（LEAK=False）
- 实测：真机体检导出的 14 条结果全部过脱敏验证；属 58 条自测断言的一部分

## ④ 面试怎么讲（约 45 秒）

「体检报告会进作品集，脱敏是硬要求。我写了 Protect-Text 函数，统一替换四类信息：机器名、用户名、内网地址、用户目录路径。关键是我不靠肉眼检查——自测脚本会程序化扫描导出报告，验证里面不含任何真实机器名和用户名，验证结果是无泄漏。连导出文件名都不含机器名，这一点和需求文档的字面建议有出入，我在 README 的已知边界里写明了原因。我的原则是：隐私必须是可验证的断言，不能是嘴上说说。」

## ⑤ 常见误解 / 坑

- **误解**：「正文替换了就安全」。文件名、页眉、系统缓存都可能漏，导出前后都要查。
- **我们踩过的坑（设计层面）**：同一信息在报告里出现二十次，漏一次就破防。所以是全文替换加程序化验证，不是抽查。
- **坑**：与需求文档字面有出入的决策（文件名也脱敏）容易被悄悄处理。我们的做法是写进 README 已知边界，留下可追溯的说明。

## ⑥ 关联词

- 三档判断（报告里每条结果的档位）
- 源码扫描自测（脱敏验证是 58 条断言的一部分）
