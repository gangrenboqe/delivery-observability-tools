# 说明 - 只读巡检

> 项目：windows-inspector · 读者：完全不懂技术的第一次求职者 · 写作日期：2026-10-11

## ① 一句话是什么

体检只看不动手，绝不改动电脑的任何设置。

## ② 为什么需要它

体检工具如果会「顺手修复」，就等于给了它改系统的权力——修错了就是事故，而且用户往往不知道被改了什么。

只读（Read-Only，只查询、不修改）是给工具划的死线：无论工具怎么用错、参数怎么传错，电脑都不会被改动。这不是建议，是红线。

没有它会怎样：用户不敢在重要电脑上运行它，「体检」变成「赌博」。

## ③ 在我们项目里长什么样

- 代码在 [Inspect-Windows.ps1](windows-inspector/Inspect-Windows.ps1)：只用 Get-*（查询类）命令，一个改状态的命令都不出现
- 数据源四件套：
  1. CIM（Common Information Model，Windows 提供的硬件与配置信息查询接口）查磁盘用量（Win32_LogicalDisk）
  2. Get-NetTCPConnection 查端口占用
  3. Get-WinEvent 查最近 24 小时系统事件日志里的严重与错误级别事件（Level 1 和 2）
  4. 注册表 Run 键 + Get-ScheduledTask 查开机自启动项（注册表是 Windows 存配置的系统数据库）
- 只读不是口头约定：[Test-Inspect.ps1](windows-inspector/Test-Inspect.ps1) 扫描源码，断言修改类命令零出现（详见「源码扫描自测」篇）
- **真实踩过的 bug（第二个真 bug）**：某次改了参数名，调用的地方没同步改——单元测试全绿、集成一跑就炸。教训是集成层必须有测试兜底，已补
- 实测：58 条断言全过；真机体检 14 条结果全部来自上述只读查询

## ④ 面试怎么讲（约 50 秒）

「这个体检工具的第一红线是只读：只用查询类命令，不碰任何能改系统状态的命令。数据源四件套：查磁盘用量、查端口占用、查 24 小时内的严重系统事件、查开机自启动项。怎么保证『只读』不是口号？我的自测脚本会扫描源码本身，任何修改类命令出现，测试直接失败。我还踩过一个集成层的坑：改了参数名，调用处没同步，单元测试全绿、集成一跑就出问题。这两件事让我形成习惯：约束要写成自动检查，跨层改动要靠集成测试兜底。」

## ⑤ 常见误解 / 坑

- **误解**：「我小心点就不会改坏」。工具是给别人用的，不能指望每个使用者都小心，也不能指望自己每次都小心。
- **我们踩过的坑（真 bug）**：参数改名没同步调用处——单元测试全绿，集成层才炸。教训：单元测试之外必须补集成测试。
- **坑**：「暂时注释掉的修改命令」也算数。死代码留在源码里同样是风险，扫描时一样不许出现。

## ⑥ 关联词

- 源码扫描自测（只读红线的执行机制）
- 三档判断（查到的数据怎么定档位）
- 报告脱敏（查到的结果怎么安全出门）
