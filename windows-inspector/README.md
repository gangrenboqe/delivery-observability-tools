# Windows 机器巡检工具（windows-inspector）

> 给一台 Windows 电脑做体检，出一份**别人看得懂**的报告。
> 覆盖磁盘、端口、服务、计划任务、开机自启、最近系统错误六类，
> 每一类都给**正常 / 警告 / 异常**三档判断，而不是只把数值打印出来。

---

## 快速开始

```powershell
# 交互式菜单（推荐：不懂技术的人也能用）
powershell -ExecutionPolicy Bypass -File Inspect-Windows.ps1

# 自测（61 项断言）
powershell -ExecutionPolicy Bypass -File Test-Inspect.ps1
```

菜单里：

```
1. 立即体检并显示
2. 只看某个项目（如磁盘）      ← 别人有时只想看磁盘，不想等全部跑完
3. 体检并导出报告到文件        ← 报告自动脱敏，可直接交付他人
4. 查看最近一次导出的报告
q. 退出
```

**依赖：无。**全部使用 Windows 自带 cmdlet，不需要装任何模块。
⚠️ 部分检查（系统错误事件）在**非管理员** PowerShell 下可能读不到，属正常现象。

## 三个设计要点（这三点才是这个作品的值钱处）

### 1. 🔴 只读

只用 `Get-*` 查询。**不启停服务、不删自启项、不清日志、不改任何配置。**

这条不是口号——自测脚本里有一条断言，**逐个检查源码里有没有 `Set-Service`、
`Stop-Process`、`Remove-Item`、`Set-ItemProperty` 这类修改命令**，有就测试失败。

> **体检和动手改是两件事。**改要单独确认，这是安全和信任的红线。

### 2. 三档判断，不是打印数值

差别很大：

| | 输出 |
|---|---|
| ❌ 只打印数值 | `C: 已用 73.7%，剩 52.7 GB` |
| ✅ 给判断 | `C: 已用 73.7% → **正常**` |

而且**噪声必须为零**。举个例子：`Windows Time` 服务是
`Stopped / 启动类型 Manual`——**按需启动的服务平时就是停的，这是正常的**。
把所有"停止"都判成异常是噪声，噪声多了等于没检查。
所以规则是：**自动启动却没运行 = 异常；按需启动且停止 = 正常。**

### 3. 🔴 脱敏是硬要求，不是可选装饰

报告要能给别人看，所以计算机名、用户名、IP、用户目录**一律替换为占位符**。
自测里有 6 条断言专门守这条。

> 真实运行结果里还包含**软件名**（浏览器、网盘、安全软件、银行输入程序…）和**账户 SID**，
> 这些同样不能进公开仓库——所以对外的样例报告里它们也都被替换了
> （见 `SAMPLE_REPORT.md`）。

## 实测结果（真机运行，已脱敏）

这台机器的真实体检结论（2026-10-11，14 条结果）：

- **磁盘**：C/F/G 盘正常，D/E 盘已用 81.9% / 83.6% → **警告**
- **端口**：监控清单里的端口均未监听（3306/6379 未占用属正常）；本机没有 3389 远程桌面在听，也没有数据库裸奔在局域网上
- **服务**：3 个正常，2 个"按需启动未运行"**正确判为正常**（不是噪声），1 个未安装 → 警告
- **计划任务**：发现 **6 个上次运行失败的任务**（显卡工具自更新、云盘更新、银行安全输入、短视频应用守护等）
- **开机自启**：**2 项指向不存在的路径**（已卸载但残留）
- **系统错误**：最近 24 小时 **0 条**严重事件

> 这份结果本身就是证据：**它查出了真实存在的问题**（6 个失败任务、2 个残留自启项），
> 而不是"一切正常"的空报告。两次运行之间失败任务从 7 个变成 6 个——
> **报告数字随机器真实状态变化，不是写死的。**

## 测试：61 项断言

`Test-Inspect.ps1` 不依赖 Pester，用最朴素的方式断言：

| 组 | 断言内容 |
|---|---|
| 三档判断 | 8 条，含**边界值**（80→警告、90→异常） |
| 脱敏 | 6 条：用户目录、IPv4、计算机名、当前用户名、空输入、无敏感信息时原样返回 |
| 只读红线 | 8 条：源码里不许出现修改类命令 |
| 检查项齐全 | 6 条：六个检查函数都在 |
| 单项检查映射 | 8 条：六类入口表齐全、菜单含「只看某个项目」（SPEC 菜单第 2 项） |
| 端口/事件三档 | 12 条：数据库端口绑 0.0.0.0→异常、只听 127.0.0.1→正常、3389→警告；磁盘错误/蓝屏/服务崩溃→异常、异常关机→警告 |
| 实际能跑 | 3 条：真跑一遍，条目数 > 0、每项都有三档判断、结果不含用户名 |
| 集成一致性 | 2 条：磁盘判断必须与阈值一致（**这一组是被真 bug 逼出来的**） |

### 🔴 开发中被自测抓到的两个真 bug（都不是看代码看出来的）

**① 判断整个颠倒了。**
函数里写了 `-HigherIsWorse` 开关，但函数体只判断了另一个开关——
于是「已用 95%」判成**正常**、「已用 50%」判成**异常**。
体检结论完全颠倒，这是最危险的一类 bug。自测当场抓到。

**② 自测漏掉了集成层。**
函数本身测对了，可我**改了参数名却没改调用处**——
真跑时磁盘 72~84% 全被判成「异常」（参数落回默认值 0）。
最后是**手动真机运行**才发现的。现在补了集成断言守住。

> 这两条是本项目最值钱的部分：
> **第一个 bug 说明"测了函数"不等于"测对了"；第二个说明"测了函数"不等于"测全了"。**

## 已知边界

- 只在 **Windows** 上可用（用的是 Windows 专有 cmdlet）
- 非管理员权限下，部分系统事件读不到
- 不做实时监控、不做定时任务、不做告警——**这是手动体检工具**
- 判断阈值是通用的（磁盘 80%/90%），**没有按不同服务器角色区分**，这是可改进项
- 导出文件名是 `巡检报告-<时间戳>.md` 而**不含机器名**：SPEC 建议的
  `机器名-体检报告-时间戳.md` 会把机器名写进要交付出去的文件名里，
  和「脱敏是硬要求」冲突——按更严的那条执行。要在文件名里区分机器的，
  导出后自己改名即可
