## 1. 一句话

读本机 AI 网关留下的调用日志，统计出一份 Markdown 报表：
**调了多少次、成功率多少、慢在哪、花了多少 token、失败都是什么原因。**

## 2. 数据源（真实存在，先确认格式再动手）

- 位置：`C:\Users\Administrator\.omniroute\call_logs/`
- 内容：每一次模型调用的记录（HTTP 状态、耗时、输入输出 token）
- 🔴 **第一步必须先看真实文件确认字段**，不要凭想象写解析。
- 🔴 **隐私**：日志里可能含请求内容或密钥 → **解析时只取数字与状态字段，正文一律不读不存**。

## 3. 输入 / 输出

| | 说明 |
|---|---|
| 输入 | 日志目录路径（命令行参数，**不写死**） |
| 输出 | `report-<日期范围>.md`（人看）+ `summary.json`（机器读） |
| 范围 | 默认全部日期，支持 `--since 2026-10-01 --until 2026-10-11` |

## 4. 报表必须包含

1. 总调用数 / 成功数 / 失败数 / **成功率**
2. 耗时：**P50 / P95 / 最大值**（🔴 明确不用平均值——平均值会把一次 30 秒的卡顿藏起来）
3. token：输入合计、输出合计、单次 Top 5
4. 失败原因分布（按状态码 / 错误类型归类）
5. 按天（或小时）的调用热度
6. 每一节都注明**统计了多少条**，数字可复算

## 5. 验收标准（不满足就不算完成）

- [ ] 用**真实日志**跑出一份报告（不许造样例数据）
- [ ] **单元测试**：分位数计算、失败归类、日期过滤（≥8 项）
- [ ] **零第三方依赖**（标准库 only，与主项目一致）
- [ ] README：是什么 / 怎么跑 / 已知边界
- [ ] 报告里**没有任何请求正文或密钥**
- [ ] 面试一句话：能脱稿讲清"为什么看 P95 不看平均值"
